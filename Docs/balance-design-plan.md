# BunkerBloom — 밸런싱 & 재미 검증 계획서

> 목표: 수치를 먼저 맞추는 게 아니라 **"플레이어가 매일 어떤 고민을 하게 만들 것인가"** 를 정한 뒤, 그 고민이 살아나도록 수치를 조정한다.

---

## 0. Context (왜 이 문서가 필요한가)

기존 BunkerBloom 작업은 "전력 이중고" 메커닉 단일 가설로 출발했음 (시작 100, 유지비 -20, 심기 -10, 수확 -20, B등급 +80, S등급 +100). 이건 **루프가 굴러가는지** 확인용이지 **재미가 있는지** 확인용은 아니었음.

가이드가 던지는 핵심:
> "재미있는 행동은 수확이 아니라 **수확 후 선택** — 작물을 식량으로 쓸까, 전기로 바꿀까, 다음 생존을 위해 남길까."

이 가설을 검증하려면 메커닉 범위가 **자원 1개(전력) → 자원 2개(전력 + 식량) + 변환 선택** 으로 확장된다.  
이 문서는 그 확장을 어떻게 할지, 코딩 전 어떻게 사전 검증할지를 정한다.

---

## 1. 핵심 가설 — Sid Meier "흥미로운 선택"

3개로 환원:

- **H1**: 작물별 자원 효율이 명확히 달라야 한다 (식량형 / 전기형 / 만능형)
- **H2**: 자원이 항상 약간 부족해서, "보유 작물을 어디에 쓸지" 고민이 매 턴 발생한다
- **H3**: 이벤트(정전·곰팡이·갈등)가 정답을 흔들어, 같은 상황도 매번 다른 답이 나온다

**검증 종착점:**  
> 10턴 플레이 동안 플레이어가 "이걸 먹일까, 전기로 바꿀까" 고민하는 순간이 **3회 이상** 발생.

## 2. 컨셉 충돌 — 결정 필요 ⚠️

가이드(일반 농작물 5종)와 BunkerBloom 원안(변이 작물 3종)이 충돌함. 결정 후 진행.

| 항목 | BunkerBloom 원안 | 가이드 제안 | 추천 |
|------|-----------------|-------------|------|
| 작물 종류 | 3종 (잿빛감자·기름덩굴·산소이끼) | 5종 (감자·버섯·옥수수·콩·약초) | **3종 유지** + 역할 매핑 |
| 자원 종류 | O2 / Food / Power / Water | Food / Power | **Food + Power 우선**, O2는 산소이끼 검증 시 추가 |
| 시뮬레이션 매체 | 게임 내 플레이 | 엑셀/스크립트 | **Python 스크립트 + 게임 양쪽** |
| 사전 합의된 수치 | 시작 Power 100, 유지비 -20 등 | 생존자 식량 10/턴, 벙커 전기 20/턴 | **가이드 기준으로 재구성** (기존 수치는 폐기) |

추천 이유:
- **3종 유지**: 한 번에 변수를 키우면 검증이 흐려진다. 작물 늘리는 건 재미 확인 후.
- **2자원 우선**: H2의 "전환 고민"을 검증하려면 최소 2자원이면 충분. 산소까지 넣으면 변수 ×2.
- **시뮬 + 게임**: 시뮬은 수학적 망함을 빨리 잡고, 게임은 손맛을 검증한다. 각자 다른 가설을 검증.
- **수치 재구성**: 기존 수치는 "Power만" 기준이라 식량 추가 시 의미가 변한다. 깨끗하게 다시.

## 3. 기준 수치 (가이드 채용)

### 3.1 소비 단위
| 항목 | 값 | 비고 |
|------|-----|------|
| 생존자 1명 하루 식량 | 10 | 가이드 기준 |
| 생존자 1명 하루 전기 | 2 | 가이드 기준 |
| 벙커 기본 전기 (벙커 유지비) | 20 | 산소정화기·조명·냉장고 합 |
| 시작 생존자 수 | **3명** | 4명은 압박 강함 → 검증 단계엔 3명 |

### 3.2 시작 자원
| 자원 | 값 | 의도 |
|------|-----|------|
| Food | **30** (3일치) | 첫 수확까지 버틸 여유 |
| Power | **50** (2일 유지비 + 액션 비용) | 잿빛감자 1번 심고 수확 도달 가능 |

### 3.3 턴 종료 자동 차감
- Food: -(생존자 수 × 10) → 3명이면 -30
- Power: -(20 + 생존자 수 × 2) → 3명이면 -26

## 4. 작물 역할 매핑 (BunkerBloom 3종)

원안 컨셉 그대로, 가이드의 효율 모델만 적용.

| 작물 | 성장 | B등급 수확량 | 식량/개 | 전기/개 | 역할 |
|------|------|-------------|---------|---------|------|
| **잿빛감자** | 2턴 | 4개 | **4** | 1 | 초반 식량 안정 (식량 16 / 전기 4) |
| **기름덩굴** | 2턴 | 3개 | 1 | **4** | 전기 전문 (식량 3 / 전기 12) |
| **산소이끼** | 3턴 | 2개 | 0 | 0 | 산소 회복 (이번 검증에선 비활성) |

### 등급 보정
| 등급 | 산출 배수 |
|------|----------|
| C (변이) | 식량/전기 효과 무효 + 페널티 (감자→ -2 전기, 덩굴→ -3 식량) |
| B (평타) | ×1.0 |
| S (PERFECT) | ×1.5 (가이드 12장 "흥미로운 선택" 유지를 위해 ×2.0보다 약하게) |

### 하루 평균 생산성 (B등급 기준)

| 작물 | 식량/턴 | 전기/턴 |
|------|---------|---------|
| 잿빛감자 | 8.0 | 2.0 |
| 기름덩굴 | 1.5 | 6.0 |

3명 + 벙커 기준 일일 필요량: **식량 30 / 전기 26** → 단일 작물로는 절대 못 막음. **반드시 두 종류를 병행**해야 생존. ← H1 활성화.

## 5. 변환 (가이드 6번 — "수확 후 선택")

수확 시 작물은 **인벤토리**로 들어감. 매 턴 종료 전에 플레이어가 슬라이더로 분배:

```
수확한 잿빛감자 4개:
[ 식량으로 □ ── 0 ─────── 4 □ 전기로 ]
```

1개당 효율 = 위 표. 즉 4개를 모두 식량으로 → +16 식량 / 모두 전기로 → +4 전기.

이게 **자원 전환 결정 지점**. H2의 핵심.

---

## 6. 이벤트 — 정답 흔들기 (H3)

정상 플레이로는 "감자=식량, 덩굴=전기"가 명확. 이벤트가 이 공식을 흔들어야 한다.

| 이벤트 | 발동 시점 | 효과 | 흔드는 답 |
|--------|----------|------|----------|
| **정전 위협** | M.03 무전 | 다음 턴 벙커 전기 -50% (40으로 점프) | 식량 작물도 전기로 변환 강요 |
| **곰팡이 번식** | 누적 수확 5회 | 다음 턴 기름덩굴 산출 ×2, 잿빛감자 +1턴 | 일시적으로 덩굴 올인 유리 |
| **배고픔의 한계** | 식량 0 1턴 → 다음 턴 즉시 | 생존자 1명 사망 | 무자비한 페널티 (식량 우선 압박) |

검증 단계엔 이벤트 3종만. 가이드 8장의 5개 엔딩은 이번 라운드 밖.

## 7. Python 시뮬레이터 사양

게임 코드 작성 전에 **수치적으로 망하는지** 빨리 확인. 손맛은 게임에서 검증.

### 입출력
- 입력: 작물 데이터, 시작 자원, 정책(전략)
- 출력: 매 턴 자원 변화, 생존 일수, 사망 사유

### 정책 3개 (Greedy / Balanced / Fixed)
| 정책 | 동작 |
|------|------|
| **Greedy** | 매 턴 가장 부족한 자원 쪽으로 100% 변환 |
| **Balanced** | 50:50 분배 |
| **Fixed-Food** | 항상 100% 식량 |
| **Fixed-Power** | 항상 100% 전기 |

### 시뮬 통과 기준 (수치 검증)
- Greedy 정책 → **10턴 이상 생존**
- Balanced → 7~10턴 생존
- Fixed (한쪽으로만) → **5턴 안에 사망**
- 이벤트 발동 시 Greedy도 **3턴 안에 위기 한 번** 경험

이 격차가 안 나오면 → 작물 효율을 더 극단으로 / 소비량을 늘려서 압박 강화.

### 산출물
- `tools/balance_sim.py` — 의존성 없는 단일 파일 Python 스크립트
- `tools/balance_sim_results.md` — 시뮬 결과 표

## 9. 검증 체크리스트 (Goal-Driven)

### A. 시뮬 통과 (코딩 전)
- [ ] Greedy 정책 10턴 이상 생존
- [ ] Fixed 정책 5턴 안에 사망
- [ ] 이벤트 미발동 vs 발동 시 생존일 차이 ≥ 2턴

### B. 코드 통과 (Step 1 게임 빌드)
- [ ] PlotCell 클릭 → Plant → Power -10, Food 변동 없음
- [ ] 턴 종료 → 식량 -30, 전기 -26
- [ ] Harvest → 분배 슬라이더 등장 → Confirm → 자원 반영
- [ ] Food 0 두 턴 연속 → 생존자 사망 로그
- [ ] Power 0 → 게임 오버

### C. 재미 검증 (10턴 플레이)
- [ ] "식량으로 / 전기로" 고민 ≥ **3회**
- [ ] 작물 2종 모두 사용
- [ ] 위기 → 회복 흐름 1회 이상
- [ ] 클리어 가능, 단 실수 1~2회로 위기 발생

A·B·C 단계마다 멈춰서 평가 → 통과 시 다음.
